# 2026-11-02

## Multi-chapter quotes from real links (#341 review)

- `parseJWLibraryLink()` now keeps `endChapter` for a cross-chapter URL such as `bible=40003001-40004011`. Before, the ending chapter was dropped, so quoting Matthew 3:1–4:11 fetched chapter 3 only.
- Merged `main` (with #342) into the branch: line-grouped edits and part-by-part fetching are both kept.
- Added regression coverage through the real link discovery and parsing path, with no mocked parser, for bulk insertion and cursor insertion (also used by the context menu). Cases: Matthew 3:1–4:11 and Matthew 3:13–4:2, whose ending verse is lower than its starting verse. Each checks all provider calls and the generated label and target.
- Validation: zero-warning ESLint, type checking, 625 Vitest tests, production build, and `git diff --check` pass. The new real-link tests fail without the parser fix.
- Manual Obsidian check still needed: quote a real multi-chapter link with the command and with the context menu.

## Automatic quote safeguards (#343 review)

- Merged the corrected #341 branch, which already includes `main` with #342.
- A created link's quote now replaces its line only when the line holds nothing but the created reference and its decorations. The anchor carries the exact text the suggester wrote, so a comma-joined multi-range reference still counts as one reference. Any other reference on the line, written before or during the lookup, is kept and the quote goes below.
- Duplicate suppression in `AutoBibleQuoteInserter` is scoped to the editor and note, so the same verse on the same line of another note is still quoted.
- Pending insertions are dropped on plugin unload (`dispose()`, registered with `Plugin.register`), and the setting is checked again before the edit. No notice is shown for an insertion that is no longer wanted.
- Regression tests: other reference on the line, reference added during the lookup, two notes quoted concurrently, setting turned off and plugin unloaded during a delayed lookup. All five fail without the fixes.
- Validation: zero-warning ESLint, type checking, the full Vitest suite, production build, and `git diff --check` pass.
- Manual Obsidian checks still needed: cursor and selection preservation, callout placement, delayed responses while editing or switching notes, disabling and unloading during a lookup, and mobile.

## Offline lookups of split parts (#341, pre-push review)

- The offline Bible clamps a range to the chapter's last verse only for the open end of a cross-chapter part (`MAX_VERSES_IN_CHAPTER`). Any other range past the chapter, such as John 3:16-40, now fails instead of giving a partial quote.
- A verse missing inside a chapter is treated as a verse the translation omits (Matt. 17:21 in the NWT) and skipped, so a whole-chapter part no longer fails offline. A range with no verse at all still fails.
- Moved the new split tests to the colocated `src/utils/splitBibleReferenceForCitation.spec.ts`, per AGENTS.md.

## Automatic quote placement (#343, pre-push review)

- A created link pushed down during the lookup, for example by the quote of the reference created just before it, is found again. It is looked for on another line only when its URL was on a single line right after it was written and still is, so an earlier mention of the same verse is never quoted instead.
- URLs are matched as whole URLs: with `noLanguageParameter`, `bible=43003016` no longer matches a quote of `bible=43003016-43003018` below it.
- The line is replaced only when the template contains `{bibleRefLinked}`, so a template without it no longer deletes the created link.
- Only a link inside a blockquote or callout gets its quote after the block. A link in a plain paragraph keeps its quote right below, even when an unrelated callout follows.
- The user's selection is kept, mapped through the insertion, instead of being collapsed to the cursor.
- An editor that can no longer be matched to a note, such as a Canvas card, keeps its quote instead of losing it.
- `AutoBibleQuoteInserter` reads the created URL with `findJWLibraryLinksInLine` instead of a third copy of the URL regex.
- Moved the new test files next to their modules as `.spec.ts`, per AGENTS.md: `src/services/AutoBibleQuoteInserter.spec.ts` and `src/utils/insertBibleQuoteForCreatedLink.spec.ts`.
- Seven regression tests, all failing without these fixes. Validation: zero-warning ESLint, type checking, the full Vitest suite, production build, and `git diff --check` pass.
